01 — Problem

A wrist device hears a lot. It should keep the promises, not the recordings.

A screenless assistant has no screen to fix mistakes on. It has to turn short, noisy voice captures into something reliable: what was said, what was decided, and who agreed to do what. It also hears other people, so names and numbers must not leak into storage or into a language model.

Real time and batch

A capture should be searchable within seconds of the button release. Summaries and commitments can wait for an end-of-day job that sees the whole meeting.

Cheap by default

Most of the day is small talk. The expensive model should only see what the cheap model and plain code could not settle.

Data

8 meetings from the AMI Meeting Corpus (CC BY 4.0), about two hours, cut into 247 captures of 30 seconds.

Answer key

28 action items written by AMI's human annotators, the human word-level transcript, and 20 questions frozen before any run.

What it is not

Hardware. The device is a simulator, and meeting microphones are not a wrist. No firmware, no Bluetooth.

02 — Approach

Local models where audio and identity are involved, a language model only on redacted text.

  1. Device events, idempotent ingestion

    Each press sends button_down, six 5-second audio chunks and button_up. The API validates every event and drops repeats by event id, so a flaky upload can be re-sent safely. Button release publishes the capture to a Redis Stream.

  2. Real-time path on the machine

    A worker reads the stream, transcribes with faster-whisper (int8, CPU), redacts names, phone numbers and emails with Presidio, embeds with bge-small, stores the redacted text in PostgreSQL with pgvector, and deletes the audio.

  3. Batch path with model routing

    Claude Haiku reads 5-minute windows and returns strict JSON, each item with an evidence quote. Plain code checks every quote is word for word in the cited capture. Failed windows go to Sonnet once. Opus makes the final call per meeting: merge duplicates, drop non-commitments.

  4. App layer

    /ask searches captures (keyword, vector or hybrid) and memories. /today lists open commitments with the captures they came from. Every model call goes to a cost ledger with a hard cap.

05 — Lessons

What broke, and what changed because of it.

  1. Privacy v1 missed half the names

    The small spaCy model removed 15 of 30 names, and Presidio rejected phone numbers with unreal area codes. Version 2 (medium model and a plain phone pattern) reached 24, 30 and 30 of 30. In the real meetings, 2 captures still keep a name.

  2. Routing saved money, not recall

    The 4 items routing missed were never extracted by Haiku. The Opus merge only removed noise, and on the human transcript it also dropped 3 true items. Next: send windows with role-assignment talk to the stronger model.

  3. The final merge was most of the routed cost

    8 Opus merge calls were about $0.10 of $0.135. Next: measure Sonnet for the merge.

  4. One run hung on a single API call

    No timeout was set. Calls now time out after 60 seconds with 3 retries, and the cost cap is checked before every call.

Limits

Simulated device. Meeting audio from table microphones, not a wrist. 28 action items and 20 questions are small sets. The real-time run is 8 captures. The leak scan only checks names someone listed.

Next

A contact list on the device for name redaction, a larger speech model for captures with numbers, stronger-model routing for assignment talk, and a week of a real wearer's captures to measure what people actually ask.

scripts/get_audio.sh ES2002a ES2005a ...                 # AMI audio (CC BY 4.0)
python eval/make_gold.py ES2002a ES2005a ...             # human answer key
